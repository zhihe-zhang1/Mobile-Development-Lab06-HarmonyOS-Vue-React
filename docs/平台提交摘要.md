# 实验六：同题异构提交摘要

本次以 HarmonyOS ArkTS/ArkUI 为本栈，对照 Vue 3 和 React。比较对象为同一个小功能：异步加载商品列表，支持搜索、收藏以及详情页跳转。完整概念映射、费曼讲解、技术选型与互评示例见《实验六_技术对比与讲解.md》。

ArkTS 使用 `@Component`、`@State`、`ForEach`、`NavPathStack`、`TabsController`、`Preferences`。Vue 3 使用 `<template>`、`ref/computed`、`v-for`、Vue Router 和 `localStorage`。React 使用 JSX、`useState/useMemo/useEffect`、数组 `map`、React Router 和 `localStorage`。三者都能完成相同的业务流程，但生命周期、渲染机制和路由历史并不完全等价。

两个异构版本都完整实现了五件商品的展示、搜索、收藏持久化、商品详情，以及 Loading/Success/Empty/Error 四种状态。Vue 3 的主要代码在 `vue3-product-demo/src/views/CatalogView.vue` 和 `DetailView.vue`；React 版本集中在 `react-product-demo/src/App.jsx`。异步服务统一放到 `src/shared/productService.js`，使用 `Promise + async/await`，并用请求序号或副作用清理避免旧请求覆盖新请求。

核心理解：组件像可重复使用的积木，状态像会自动更新的电子价签，异步请求像取餐号，普通路由是翻到另一页，Tab 是在同一资料夹里切换标签；本地存储像抽屉而不是保险柜，因此不能放明文密码和敏感令牌。

选型上，HarmonyOS 原生设备功能优先 ArkTS；小中型 Web 界面可选 Vue 3；复杂组件复用和大型前端团队可考虑 React。互评中应先肯定具体的实现，再提出可复现、可修改、可验证的建议，例如增加失败状态、清理旧请求或检查收藏刷新后是否恢复。

运行：分别进入两个 Web 工程执行 `npm install`、`npm run dev`，也可执行 `npm test`。原生 ArkTS 工程在 DevEco Studio 中运行。
